## 建議的共用能力開發優先序

**P0｜先補可跨作品使用的狀態與動作原語**

1. **持續狀態／延遲效果與取消**：REST 後跳過下次 ACTIVE、效果持續到某階段、角色離場取消狀態、同時觸發排序。源例：`BLC-1-003`、`BLC-1-006`、`BLC-1-031`、`SAO-1-034`、`MST-1-054`。不得將人類可以選擇已 REST 角色的合法規則與 AI 最佳選擇混為一談。
2. **跨區域物理 UID 動作及進場來源**：場外或手牌特殊登場，滿場替換，REST/ACTIVE 入場，原卡回手或進場後 onPlay，移動／位置互換；防止 UID 複製與資訊外洩。源例：`BLC-2-043`、`SAO-2-001`、`MST-1-004`、`MST-1-068`。與已存在的 onOutsideRecover/014 free-entry 效果區分，不重做。
3. **Raid 層與退場事件總線**：底板繼承、最上層剝離、不同離場類型、Raid 下層重出場、觸發延後結算。源例：`BLC-1-023`、`BLC-4-033`、`TTG-1-008`、`MST-1-068`。現有 TTG-1-073 pilot 與 onRetire 應作既有基礎。

**P1｜提升組合效率與資料驅動能力**

4. **泛化選項隊列與執行次序**：現有 `chooseOne` 支援限定兩模式；未來應支援來源驗證後的多模式、模式條件、模式內序列與多目標，但不可將不相容的印刷效果硬編成通用模板。源例：`BLC-2-002`、`TTG-1-017`、`SAO-1-033`、`MST-1-068`。
5. **牌庫窗口泛化**：查看 TOP N、候選篩選（名稱／特徵／顏色／能源）、其餘放頂／底／場外及獨立排序、公開與隱藏資訊、棄牌條件。源例：`BLC-1-028`、`TTG-1-026`、`SAO-1-005`、`MST-1-065`。優先組合已有 TOP-N ops，不重寫。
6. **名稱別名與身份語義**：對名稱查詢、Raid 底板、條件效果與卡片 UID 做正式印刷別名匹配，而不是直接改變 `cardId`。源例：`SAO-2-003`、`SAO-1-010`、`BLC-4-001`、`MST-1-068`。
7. **持續 BP／產能與額外費用**：多角色名稱／特徵條件、能源門檻與全場產能、AP 追加與降低、當回合能力授予。源例：`TTG-1-003`、`TTG-1-040`、`BLC-1-007`、`MST-1-068`。延續既有 `passiveBonuses`、`frontGeneratesEnergy`，而非建立另一套計算器。

**P2｜把能重用的簡單效果轉換成已驗證真卡**

8. 從各作品挑選完整印刷能力皆能由既有 DSL 表達的卡，加入資料、官方指紋、正負例測試與合法真卡對局。若是複合卡，其中任何一項能力未支援則不得直接計為已移植。

## 每批驗收與完成定義

- 每小批先證實官方日文印刷全文與有關 FAQ／勘誤，然後完整實作一張或一組官方卡的所有能力（包含生命 Trigger）。
- `legalUniversalActions` 必須給出正確合法選項；不合法 actor/UID/zone/時機/成本在狀態改動前拒絕。
- 同一新能力至少用不同作品的真實卡測試（若此能力確實出現在多作品），另測 UI 選項文字與 Normal/Hard AI 選擇；同步測試 UID 守恆、隱藏資訊、Raid 層與全場滿格。
- 單批有針對性測試與 commit；一組 3–5 批後完整跑 Node 22 `npm test`、`node scripts/v2-integrated-match-matrix.mjs` 和 `node scripts/v2-unported-report.mjs`，CI 綠才算驗證完成。
- 成效分三欄：新增引擎能力、該能力已有的真卡測試、真正淨新增完整 V2 卡片數。**不要使用分類命中數充當可立即移植數**。
